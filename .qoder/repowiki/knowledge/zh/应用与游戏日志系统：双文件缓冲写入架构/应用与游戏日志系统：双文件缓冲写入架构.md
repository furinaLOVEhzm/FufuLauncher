本仓库采用自实现的轻量级日志系统，未引入第三方日志框架（如 Serilog、NLog），而是通过 App.xaml.cs 中的静态方法与 GameLogService 服务分别管理两类日志，均以「内存队列 + 定时批量刷新」模式写入文件。

1. 系统组成
- 应用日志（App.xaml.cs）：提供 WriteAppLog/ReadAppLog 静态方法，使用 ConcurrentQueue<string> 缓冲 + 200ms Timer 批量写入 app.log；异常捕获（DispatcherUnhandledException、AppDomain.UnhandledException、TaskScheduler.UnobservedTaskException）统一写入该文件。
- 游戏日志（GameLogService.cs）：通过 Process.OutputDataReceived/ErrorDataReceived 实时捕获 Minecraft 进程 stdout/stderr，写入独立的 game.log；内部维护 StringBuilder 内存缓冲（上限 5000 行，超出裁剪最早行）+ ConcurrentQueue 待写队列 + 200ms 定时器批量落盘。

2. 关键文件
- src/FufuLauncher/App.xaml.cs：应用入口、全局异常捕获、app.log 缓冲与读写
- src/FufuLauncher/Services/GameLogService.cs：游戏进程日志捕获、game.log 写入、LogsAppended/LogAppended 事件
- src/FufuLauncher/Services/GameLaunchService.cs：启动游戏时注入 GameLogService 并 AttachToProcess
- bootstrap/Program.cs：Go 打包前的引导程序，使用本地 Log(string) 输出构建过程信息（非运行时日志）

3. 架构与约定
- 双文件分离：app.log（应用生命周期、异常、诊断）与 game.log（Minecraft 进程输出）完全独立，互不混杂。
- 统一写入路径：所有日志均位于 AppDataDir = Path.Combine(AppContext.BaseDirectory, "appmcGAME") 下。
- 批量写入策略：两个子系统均采用「ConcurrentQueue + 200ms Timer」模式，避免逐行 IO 阻塞 UI 线程。
- 时间戳格式：应用日志为 [yyyy-MM-dd HH:mm:ss]，游戏日志为 [HH:mm:ss]。
- 事件驱动 UI 更新：GameLogService 暴露 LogsAppended（批量）和 LogAppended（单行兼容）事件，供 UI 订阅。
- 资源清理：GameLogService 实现 IDisposable，在 Dispose 中 DetachFromCurrentProcess、FlushPendingToFile、释放 Timer。

4. 约束与规范
- 日志写入失败被静默忽略（try/catch 包裹 File.AppendAllLines/File.AppendAllText），确保异常不影响主流程。
- 游戏日志内存缓冲有硬上限（MaxBufferLines = 5000），防止长时间运行导致内存膨胀。
- 读取日志前强制 FlushNow/FlushAppLogQueue，保证 ReadAppLog/FullLog 返回最新内容。
- 未使用结构化日志字段或日志级别枚举，仅通过字符串前缀（如 [登录]、[异常-UI]、[stderr]）区分来源。
