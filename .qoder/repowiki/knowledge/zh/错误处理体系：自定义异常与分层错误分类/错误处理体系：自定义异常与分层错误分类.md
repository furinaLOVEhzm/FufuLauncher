该仓库在 C# WPF 主程序、C# Bootstrap 引导程序和 C++ 原生模块中采用分层错误处理策略，核心围绕自定义异常类型与枚举分类展开。

**1. 系统/方法**
- 使用 .NET 标准异常机制（`Exception` 派生类）而非返回码或 `throw null`。
- 通过自定义 `AuthException` + `AuthError` 枚举对认证相关错误进行细粒度分类（网络异常、未购买 Minecraft、用户取消、设备码过期、令牌交换失败、未知错误），供 UI 层差异化提示。
- Bootstrap 程序统一在 `Main` 顶层 `try/catch (Exception)` 捕获所有未处理异常，以红色控制台输出并返回退出码 99。
- C++ 原生代码使用 `new(std::nothrow)` 分配内存并在失败时返回空指针，避免抛出 C++ 异常跨边界。

**2. 关键文件与包**
- `src/FufuLauncher/Services/AuthService.cs`：定义 `AuthError` 枚举和 `AuthException` 异常类，集中封装微软 OAuth/XBL/XSTS/Minecraft 登录链路的错误分类与转换。
- `src/FufuLauncher/Interaction/DeviceCodeDialog.cs`：UI 交互层将轮询过程中的异常（包括用户取消）转换为 `AuthException(AuthError.Cancelled, ...)` 向上抛出。
- `bootstrap/Program.cs`：构建引导程序，大量使用 `DirectoryNotFoundException`、`FileNotFoundException`、`InvalidOperationException` 表达环境配置错误，并通过 `DownloadWithFallbackAsync` 实现多镜像源回退下载。
- `native/FufuNative/HashUtil.cpp`：C++ 侧使用 `std::nothrow` 内存分配模式，避免异常跨语言边界传播。
- `src/FufuLauncher/App.xaml.cs`：应用生命周期入口，在 `Shutdown` 阶段用 `try/catch { /* ignore */ }` 忽略资源释放异常，保证清理过程健壮性。

**3. 架构与约定**
- **服务层抛出自定义异常**：`AuthService` 将所有网络请求、JSON 解析、HTTP 状态码异常统一包装为 `AuthException`，并附带 `AuthError` 枚举值，调用方可按错误类型分支处理。
- **UI 层消费异常**：`DeviceCodeDialog` 将后台轮询任务中的异常提取并重新抛出，用户取消场景明确抛出 `AuthError.Cancelled`。
- **Bootstrap 严格校验**：构建流程中对缺失文件、无效路径、进程启动失败等使用具体异常类型（`DirectoryNotFoundException`、`FileNotFoundException`、`InvalidOperationException`），配合彩色控制台日志便于诊断。
- **容错式清理**：多处 `try { ... } catch { /* ignore */ }` 用于非关键操作（剪贴板写入、文件删除、资源释放），确保主流程不被副作用中断。
- **回退重试模式**：`DownloadWithFallbackAsync` 遍历多个下载源，记录最后一个异常并在全部失败后抛出聚合异常；`PollDeviceCodeAsync` 对 `HttpRequestException` 自动延迟重试。

**4. 约定与约束**
- 认证相关错误必须通过 `AuthException` + `AuthError` 枚举表达，禁止直接抛出原始 `HttpRequestException` 到 UI 层。
- Bootstrap 程序的每个关键步骤都验证前置条件并抛出明确的 .NET 内置异常，便于自动化脚本检测失败原因。
- C++ 原生代码不向 C# 抛出异常，仅通过返回值或空指针传递错误状态。
- 非致命操作（剪贴板、临时文件删除、资源释放）一律使用空 `catch` 块忽略异常，保证主流程鲁棒性。
