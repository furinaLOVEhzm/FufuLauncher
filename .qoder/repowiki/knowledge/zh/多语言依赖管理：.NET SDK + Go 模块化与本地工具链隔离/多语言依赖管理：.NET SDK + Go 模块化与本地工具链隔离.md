本仓库采用多语言混合架构，依赖管理按语言域划分，分别使用 .NET SDK（NuGet）和 Go Modules，并辅以本地工具链隔离策略。

1. 系统/工具
- .NET 8.0（net8.0 / net8.0-windows）作为主运行时，通过 Visual Studio 2022 解决方案 `FufuLauncher.sln` 统一编排 C# WPF、C++ 原生 DLL、Go 打包器与引导程序。
- Go 1.26.5 工具链以压缩包形式存放在 `.tools/go1.26.5.windows-amd64.zip`，配合 `.tools/gopath` 与 `.tools/gocache` 实现 GOPATH 与工作缓存的完全隔离，避免污染系统全局 Go 环境。

2. 关键文件与包
- `src/FufuLauncher/FufuLauncher.csproj`：主项目声明 `Microsoft.Extensions.DependencyInjection` v8.0.1 作为唯一 NuGet 依赖；通过 `<PackageReference>` 引入，未使用 `packages.config`。
- `bootstrap/bootstrap.csproj` 与 `tools/proc/proc.csproj`：均为 .NET 8.0 控制台应用，未声明任何外部 NuGet 包，仅依赖框架内置库。
- `packager/go.mod`：Go 模块 `fufu-packager`，声明 `go 1.21`，当前无第三方依赖（无 `require` 段），构建产物为独立可执行文件。
- `native/FufuNative/*.vcxproj`：C++ 原生 DLL 由 VS2022 编译，不经过 NuGet/Go 依赖管理器。

3. 架构与约定
- .NET 项目全部采用 SDK 风格 `.csproj`，目标框架统一为 `net8.0` 或 `net8.0-windows`，启用 `ImplicitUsings` 与 `Nullable`，语言版本固定为 `latest`。
- 所有 .NET 项目均设置 `IsPackable=false`（除主程序外），表明这些是内部工具而非可发布 NuGet 包。
- C++ 原生 DLL 通过 `<None Include="..." CopyToOutputDirectory="PreserveNewest">` 在构建时复制到输出目录，并按 `runtimes\win-x64\native\FufuNative.dll` 链接路径组织。
- Go 打包器位于 `packager/`，通过 `go mod` 管理，但当前无外部依赖；Go 运行时与工具链通过 `.tools/` 目录本地化，构建脚本应指向该路径下的 go 二进制。

4. 约束与规范
- 未使用 `vendor/` 目录进行依赖锁定，NuGet 依赖通过 `PackageReference` 版本号显式声明，但未生成 `packages.lock.json`。
- Go 侧未使用 `go.sum` 或私有代理（GOPROXY/GOPRIVATE），因当前无第三方依赖。
- 所有 .NET 项目将 `RuntimeIdentifier` 固定为 `win-x64`，并以 `SelfContained=false` 依赖宿主运行时。
- 版本信息集中在各 `.csproj` 的 `<Version>/<AssemblyVersion>/<FileVersion>` 中，主程序当前为 `1.0.5.1`。
